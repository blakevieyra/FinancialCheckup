# Production deployment checklist — Financial Checkup

Use this after deploying to **Render** (or any paid host) to confirm the app is secure and ready to scale.

## Render services

| Service | Plan | Purpose |
|---------|------|---------|
| `financialcheckup-api` | Starter or higher | Node API |
| `financialcheckup-web` | Static | Vite client |
| `financialcheckup-db` | basic-256mb+ | Postgres |

## Required environment variables (API)

Set these in the Render dashboard for **financialcheckup-api**:

| Variable | Notes |
|----------|--------|
| `JWT_SECRET` | Auto-generated by blueprint |
| `DATABASE_URL` | Linked from Postgres |
| `CLIENT_URL` | **Your live web URL**, e.g. `https://financialcheckup-web.onrender.com` |
| `VITE_API_BASE_URL` | Set on **web** service to API URL, e.g. `https://financialcheckup-api.onrender.com` |

### Email (required for registration)

| Variable | Notes |
|----------|--------|
| `SENDGRID_API_KEY` | SendGrid API key |
| `MAIL_FROM` | Verified sender, e.g. `noreply@yourdomain.com` |

Without email, production blocks legacy one-step registration; users must use OTP verify flow.

### Stripe (if billing enabled)

| Variable | Notes |
|----------|--------|
| `STRIPE_SECRET_KEY` | Live secret key |
| `STRIPE_WEBHOOK_SECRET` | From Stripe webhook endpoint → `https://YOUR-API/api/billing/webhook` |
| `STRIPE_PRICE_*` | Price IDs from your Stripe account |

## Post-deploy verification

1. **Health:** `GET https://YOUR-API/api/health` → `{ "status": "ok", "db": "ok" }`
2. **Register:** New account receives OTP email
3. **Login / checkup:** Score updates after Finances data entry
4. **Stripe:** Test checkout + webhook in Stripe dashboard (Events → succeed)
5. **Delete account:** Cancels Stripe subscription before user row is removed
6. **Privacy:** `https://YOUR-WEB/privacy.html` loads

## Security features (built in)

- Helmet security headers
- CORS allowlist (`CLIENT_URL` + Capacitor mobile origins)
- Rate limits: auth, API, guest checkup preview, support
- `trust proxy` for correct IP limits behind Render load balancer
- bcrypt (cost 12) passwords, HS512 JWT
- Parameterized SQL (Postgres)
- Stripe webhook signature verification + idempotency table
- Generic 500 errors in production (no stack traces to clients)
- Graceful shutdown (SIGTERM drains HTTP + DB pool)

## Scaling notes

- **PG_POOL_MAX** — default `10`; raise on larger API instances if you see pool timeouts
- **Render API** — upgrade instance if CPU spikes on AI routes (`/api/ai`, `/api/expert`)
- **Anthropic** — rate-limit at provider; app rate-limits authenticated API globally
- **Postgres** — upgrade plan before ~1000+ active users with heavy history writes
